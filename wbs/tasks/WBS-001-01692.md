# 目的

選択された入力形式・PD曲・編曲設計から、JSON Version 2または承認済み境界まで変換する最小prototypeを実装する。

# 作業内容

deterministic処理、source/provenance追跡、intermediate artifact、machine validation、既存pipeline接続を実装する。production品質や新しい作曲ruleは保証・追加しない。

# 入力

01689のJSON適合性、01691のHuman選択、01688の編曲設計。

# 成果物

PD曲自動編曲prototype、テスト、実行記録。

# 完了条件

承認された入力から再現可能な中間artifactを生成し、適合性・検証境界を確認できる。

# 完了にしてはいけない条件

権利未確認sourceの使用、silent fallback、production品質の主張、既存pipelineの無根拠変更は完了にしない。

# 確認結果

Humanが選択したMutopia `Maple Leaf Rag (Mutopia-2011/11/13-23)`のMIDIを入力として、標準ライブラリのみの決定的SMF parser、MusicXML writer/parser、NormalizedScore、ArrangementPlan、JSON Version 2 emitterを実装した。source URLと01690証跡のSHA-256 `3dd712a85fabd267f5a2cee5cb23af4683408c2f29b8814721844498f1ee4f66`を照合し、不一致時はrejectする。prototype実行で生成したMusicXMLのSHA-256は`955fe1a837bc69c188efe76836e1f5b8fc3c9307a9bc4df29df6f6e2728beab4`である。

NormalizedScoreとArrangementPlanを分離し、source event ID、role、physical channel、quantization、pitch transform、polyphony omission、range rejection、repeat/loss、CH4 unused policyをmanifest/reportへ保存した。Maple固有設定はmelody→CH1、harmony/accompaniment→CH2、bass→CH3、CH4 unused、grid 30 source ticks、JSON TicksPerRow 6、loop none、one 64-row JSON pattern windowであり、production defaultや全曲完成を主張しない。MIDI由来のvoices/staff/spellingはreconstructed、repeats/endings/articulation/dynamics/notation semanticsはlost/unknownとして明示した。

生成JSONは既存JSON Version 2のvalidator/buildを通過し、既存`json_to_uge.py`でUGE、`json_to_huge_asm.py`でASM、`analyze_uge.py`で構造解析できた。JSON仕様、既存converter、ROM、SameBoyは変更・実行していない。manifest/report/XML/JSONは一時出力で再生成し、同一入力・設定でMusicXML、JSON、manifest hashが一致した。

テストは`python3 -m unittest tests/test_maple_leaf_rag_prototype.py`（2件成功）、`python3 -m unittest tests/test_json_to_uge.py tests/test_analyze_uge.py tests/test_generated_uge_validation.py`（229件成功）を実行した。全tests discoveryは既存`tests/test_validate_wbs.py`のWBS件数固定値679に対し現行696となる失敗が1件あり、今回のprototype実装とは無関係な既存テストの陳腐化として記録する。
