# 目的

Humanが選択した入力からGame Boy 4chへ落とす自動編曲処理の責務と設計境界を整理する。

# 作業内容

CH1/CH2 pulse、CH3 wave、CH4 noise、melody priority、polyphony reduction、harmony/accompaniment、bass、percussion、octave/range、quantization、tempo/TicksPerRow、phrase/section、repeat/loop、instrument、unsupported情報、conflict resolutionを設計する。旧generatorの作曲ruleをそのまま流用せず、根拠のないproduction defaultを確定しない。

# 入力

01687のHuman選択、01685の要件、既存Game Boy/JSON契約。

# 成果物

自動編曲設計文書、変換境界、未確定事項。

# 完了条件

選択入力から4ch編曲・JSON接続を実装可能な粒度で記録する。

# 完了にしてはいけない条件

入力や権利が未確定なのに具体的production ruleを決めた場合は完了にしない。

# 確認結果

MusicXML固有構造とGame Boy物理channelの間に正規化・logical role・ArrangementPlanの境界を設計し、melody選択、polyphony/harmony/bass/percussion縮約、pitch/range、quantization、tempo/TicksPerRow、phrase/section、repeatとBGM loop、instrument mapping、channel allocation、SFX共存、loss/warning、determinism、configuration、JSON Version 2 handoffを実装可能な粒度で整理した。具体的production default、parser、source、prototype、JSON変更は決定していない。

# 証跡

`docs/generated-pd-arrangement-design.md` に、MusicXMLからJSON Version 2までの責務境界、4ch capability、logical roleとphysical channelの分離、時間モデル、loop、SFX境界、unsupported/lossy変換、再現性、設定点、01689とprototypeへのhandoffを記録した。
