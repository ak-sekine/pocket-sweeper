# 目的

自動作曲でルール不足・検証失敗・人の評価上の問題が見つかった場合に、根拠なく新規ルールやdefault値を追加せず、問題種別に応じて資料調査・仕様確認・実装確認・人の評価へ戻す運用を定義する。
# 作業内容

ルール不足・人の試聴で問題が見つかった場合に、21曲の多数派を根拠にせず、資料調査・実装確認・人による評価のどこへ戻すかを定義する。仮説と確定ルールを分離する。
# 入力

ルール変更プロセスと記録項目。
# 成果物

`docs/composition-rule-evidence-return-workflow.md` に、既存rule確認、problem type、return-to matrix、evidence conflict、Human evaluation loop、machine validation failure、rule creation/modification gate、hypothesis/provisional、default gate、corpus observation、decision record、stop/escalation、supersession、01576 stage対応、Case A〜F、review checklistを記録する。
# 完了条件

根拠なしのルール追加を防ぐ判定手順を記録する。
# 完了にしてはいけない条件

人による確認が必要な場合、確認結果がない状態で完了にしない。
# 確認結果

01575・01576が`complete`であることを確認した。既存rule・applicability・capability/constraint・theory/policy・layer/channel・implementation/Human evaluationの誤用を確認してから根拠不足候補へ進む手順を定義した。corpus observationを品質根拠やdefaultに使わず、SFX conflictを未解決のまま保留できる運用とした。新規GUI・試聴・実機確認、generator/analyzer/converter変更は実施していない。
# 証跡

`docs/composition-rule-evidence-return-workflow.md` の問題分類・戻り先表、decision template、rule gate、停止・エスカレーション条件、SFX conflict、Case A〜F、review checklist。根拠不足時にconfirmedへ進めない運用を確認可能な形で記録した。
