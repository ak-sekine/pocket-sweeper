# 目的

承認済みsourceから自動編曲prototype、JSON、UGE、ASM、確認用ROMまでをend-to-endで生成する。

# 作業内容

既存pipelineを可能な限り再利用し、source-to-artifact追跡、converter success、UGE validation、ASM生成、RGBDS build、artifact hash、repeatability、loop、tempo/TicksPerRowを確認する。build成功と音楽品質を分離する。

# 入力

01692のprototypeとapproved source。

# 成果物

JSON、UGE、ASM、ROM、manifest、validation記録。

# 完了条件

1曲以上でsourceからROMまでの追跡可能な機械検証済みprototype artifactを生成する。

# 完了にしてはいけない条件

source混在、検証失敗の隠蔽、build成功を音楽品質の証拠とした場合は完了にしない。

# 確認結果

Human承認済みのMutopia `Maple Leaf Rag (Mutopia-2011/11/13-23)` MIDIを一時領域へ取得し、期待SHA-256 `3dd712a85fabd267f5a2cee5cb23af4683408c2f29b8814721844498f1ee4f66`をprototypeの入力検証で確認した。`maple_leaf_rag_prototype.py`を2回実行し、MIDI全体をNormalizedScore化したうえで、JSON/UGE/ASM/確認用ROMは64-row prototype windowとして生成した。MusicXML、JSON、manifest、report、UGE、ASM、ROMの全hashが2回で一致した。

生成JSONは既存Version 2 validator、UGEは`analyze_uge.py`、ASMはRGBDS assembler/linker/fixer、ROMは`build_sound_test_rom.py`を通過した。source BPM 120（500000 microseconds per quarter）とruntime TicksPerRow 6は別metadataとして維持し、JSON loopは`none`、ASM loop metadataもnoneとして確認した。生成物は`/tmp/pocket-sweeper-01693`に保存し、source MIDIや生成sourceをrepositoryへ追加していない。音楽品質、Human試聴、本番BGM採用は01694以降の評価対象である。

# 証跡

詳細なpath/hash、コマンド、RGBDS version、UGE/ASM/ROM検証、再現性、既知の制限は`docs/generated-pd-maple-leaf-rag-end-to-end.md`に記録した。source identity、conversion provenance、64-row境界、BPM/TicksPerRow分離、loop noneを含む。
