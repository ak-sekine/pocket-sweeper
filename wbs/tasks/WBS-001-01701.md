# 目的

ArrangementPlanからJSON Version 2、UGEまでのnote/timing保存性を検証する。

# 作業内容

JSON row、instrument、order、pattern、tempo/TicksPerRow、loop metadataとArrangementPlanを比較する。

# 入力

01698〜01700の比較結果、JSON、UGE、analyzer出力。

# 成果物

JSON/UGE保存性reportとruntime境界の未確認事項。

# 完了条件

JSON/UGEのnote/timing差分と、形式検証で確認できないruntime事項を分離して記録する。

# 完了にしてはいけない条件

UGE parse成功を原曲性保持や音楽品質の証拠にしない。

# 確認結果

01700の31 selected ArrangementPlan eventsを基準に、prototypeのJSON Version 2生成と`json_to_uge.py`を再実行して比較した。JSON pattern emissionでは31件中26件がencoded、5件が64-row pattern overflow、JSON note pitch exactは6件、row exactは3件だった。JSONの26 note cellsはUGEの26 note cellsへ全件exact（note value/instrument）に変換された。JSON/UGE Version 6 structure、pattern/order/channel/instrument、TicksPerRow 6、loop noneを解析し、source BPM 120とは分離した。UGE analyzerのimplicit cycleとintended loop noneも別記録した。runtime再生やHuman評価は未確認である。

# 証跡

JSON/UGE比較、analyzer出力、hash、実行command、unit testを`docs/generated-pd-maple-leaf-rag-json-uge-preservation.md`へ記録した。
