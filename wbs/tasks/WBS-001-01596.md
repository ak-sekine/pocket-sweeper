# 目的

Human試聴で問題が報告された候補について、生成構造・変換経路・既存自動検証・Human evidenceを区別して原因と未確定事項を分析する。
# 作業内容

seed 1/5/7をlogical generationからJSON/UGE/ASM/ROMまで追跡し、profileの4 logical layerとmelody-only/CH1 allocation、note/rest、pitch、pattern/order、loop、既存test coverageを確認した。原因を推測で確定せず、修正は実施しない。
# 入力

01594 Human結果、01593 candidate artifacts、generator/profile/converter/analyzer/builder、既存仕様とテスト。
# 成果物

`docs/generated-song-candidate-analysis.md`のpipeline trace、candidate比較、confirmed/not confirmed分類、後続引き継ぎ。
# 完了条件

自動検証・資料根拠・人の試聴を区別して原因と未確定事項を記録する。
# 完了にしてはいけない条件

人による確認が必要な場合、確認結果がない状態で完了にしない。
# 確認結果

3候補すべてでlogical melodyには6 event（有音2、rest 4）があり、JSON/UGE/ASMにも有音2 noteが対応していた。一方、candidate profileは4 logical layerを生成するが変換対象はmelodyのみ、allocationはCH1のみだった。自動検証は形式・構造・生成成功を保証するがruntime発音や音楽品質を保証しない。Humanの「1音」観測に対するconfirmed causeは特定できず、generator/profile/layer/allocation/converter/driver/ROM/SameBoy等をnot confirmedとして整理した。実装・profile・rule・candidateは変更していない。
# 証跡

`docs/generated-song-candidate-analysis.md`、seed 1/5/7の実測値、原因未確定と後続分析への引き継ぎ。
