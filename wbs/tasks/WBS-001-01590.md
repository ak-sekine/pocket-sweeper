# 目的

master seedとcaller-owned生成入力を一元化し、全logical layerを同一条件で再生成できることを機械検証する。
# 作業内容

01579の`GenerationContext`を再利用し、structure→melody→accompaniment→bass→noiseを1つのshared streamで順番に生成する`LogicalGenerationPlan`/`LogicalGenerationResult`を追加した。既存JSON/ASM/ROM converterは再実装せず、seed再現性の範囲と限界を文書化した。
# 入力

同一generator version、master seed、parameters/options、candidate ordering、pattern/rule definitions、resolution/allocation context。
# 成果物

全logical layerの決定的dict再現、global random非依存テスト、seed再現性契約文書。
# 完了条件

複数seedでCompositionStructure、Melody、Accompaniment、Bass、Noiseの`as_dict()`が一致し、既存APIを壊さない。JSON/ASM/ROMは既存変換契約の範囲に留め、01591の一括CLIは作らない。
# 完了にしてはいけない条件

SameBoy、実機、hUGETracker、試聴、音楽品質、SFX共存を確認済みと扱わない。
# 確認結果

01579との差分として、個別probeではなくmaster seedから全logical layerを固定順のsingle shared contextで生成する契約を追加した。stage-specific sub-seedは現行single-stream契約を変更するため導入せず、将来課題として記録した。seed 0/1/42/-1/巨大整数で全logical resultの決定的dict一致、global random状態非依存を確認した。seed単独では曲を決めず、caller inputとgenerator versionを再現条件とした。
# 証跡

`docs/generated-song-seed-reproducibility.md`、`tools/bgm_generator.py`の`LogicalGenerationPlan`/`generate_logical_composition`、専用再現性テスト。
