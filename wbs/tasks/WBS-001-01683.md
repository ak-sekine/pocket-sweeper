# 目的

01680〜01682の整理・調査・比較をHumanが確認し、次に試す自動作曲方式を選択できる状態にする。

# 作業内容

Humanが、候補方式のうちどれを試すか、複数方式を組み合わせるか、または自動作曲検討自体を停止するかを判断する。Codexは方式を先に選択しない。

# 入力

01680の技術基盤整理、01681の候補方式調査、01682の比較結果。

# 成果物

Humanによる方式選択または検討停止の判断と根拠。

# 完了条件

Humanが次に試す方式、組み合わせ、または停止判断を記録する。

# 完了にしてはいけない条件

Humanの判断なしにCodexだけでcompleteにしない。

# 確認結果

Humanは次のように判断した。

「パブリックドメイン曲を元にした自動編曲を検討したいと思います。既存のJSON Version 2 → UGE → ASM → ROM基盤 は基本は維持する方針で行きたいと思います。問題があれば変更しても問題ありません。」

次に試す方式は、01681/01682のApproach A「既存曲・パブリックドメイン曲を基礎にした編曲」とする。完全自動によるゼロからの作曲、AI/LLM生成、corpusからの新曲生成、旧generatorのparameter tuningを今回の次方式として選択したものではない。これらを将来永久に除外する判断でもない。

既存のJSON Version 2→UGE→hUGEDriver ASM→ROM基盤は基本的に維持する。ただし、JSON Version 2で必要情報を表現できない、MIDI/MusicXMLとの変換境界に不都合がある、4ch reduction・quantization・loop・instrument/channel mappingで具体的な技術問題が確認される等の場合は、根拠を記録した上で変更を検討できる。現時点で先回りした変更は行わない。

# 証跡

Humanの選択結果と原文を本WBSに記録した。PD曲・楽譜・MIDI/MusicXML・採譜データ・編曲・録音のlicense/provenanceは未解決事項として維持する。次工程では、PD曲を元にした自動編曲方式の具体化が必要である。
